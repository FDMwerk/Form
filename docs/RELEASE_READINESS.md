# Form release readiness — 2026-11-07

Status: **preview 0.3 preparation**. Reviewed application source, build instructions, original test fixtures and policies are public at [FDMwerk/Form](https://github.com/FDMwerk/Form). No App Store submission, App Store approval, notarization or production binary distribution is claimed by this review. This document records evidence and remaining release gates rather than certifying compliance.

## Implemented in the source

- Universal macOS target for arm64 and x86_64, minimum macOS 14; public AppKit and WKWebView APIs and one self-contained app bundle.
- App Sandbox and user-selected **read-write** file access for explicit PNG screenshot saves; imported model files are read only. Native file reads are serialized, occur off the main thread, check the supported extension and regular-file status, and cap the actual bytes read at 250 MB. Security-scoped access is ended after reading. Original models are never written by the native importer.
- The network-client entitlement is present because it was required for WebKit process startup on the development system. Form has no model-upload, analytics, account, AI-service or updater implementation. Its bundled viewer restricts remote origins through a Content Security Policy. The bundled importer needs JavaScript/WebAssembly evaluation; it is not fetched from a runtime service.
- Native bridge messages are accepted only from the main bundled viewer document. Navigation stays within the app's Web resources. Explicit documentation/support links open externally. Main and legal views use non-persistent WebKit website data stores.
- Explicit PNG screenshot save uses the macOS Save dialog and atomic writes. Native validation checks PNG signature, ImageIO decoding, payload size (50 MB maximum) and pixel bounds (10,000 pixels per dimension, 32 megapixels maximum) before offering a destination. The titlebar has a narrow native drag region that does not capture viewport gestures.
- “Open With” uses a per-import opaque UUID mapped to the original file only after successful import. On-demand LaunchServices discovery and known installed bundle IDs are filtered by file format, own/old Form identity, build/archive paths and duplicates. Native menus use the installed app icons. Standard apps receive the original URL; Blender receives a fixed import script and literal separated arguments in a new instance. Browser drops without a native source URL remain disabled. Tests execute the actual script against a mock Blender API; a real external launch/import integration check remains necessary.
- Standard multi-file Open dialog, Finder open-file events and drag/drop. Successful native imports are added to macOS recent documents; rejected imports are not added. The app does not itself change default file associations.
- Privacy manifest: no tracking, no collected-data declarations, and UserDefaults reason **CA92.1** for app-local navigation/display preferences. Saved values are limited to known profile/language codes, bounded finite speeds, booleans and a validated hex color. The language defaults to the macOS language preference, with a catalog/base-language fallback to English. Privacy and license information are accessible in-app.
- Toolbar symbols use Lucide ISC assets. The publisher approved the original folded-F app and FDMwerk logo; it is not the Lucide Box glyph. No OpenAI logo or affiliation claim appears in the product. Names of navigation-profile applications describe the mappings and do not imply affiliation.
- MIT application source, third-party notices and a pinned dependency lockfile. CAD importer/WASM resources remain separately replaceable and can be rebuilt/re-signed with Form. Exact importer and OCCT source archives were acquired locally for the corresponding-source release package.
- The bundled reference is now a textured **apple**, normalized to an 80 mm largest bounding dimension. Tripo Pro status was observed. Apple asset ID: `0f0757df-9396-47f8-b9d8-760b9294bf8a`. Apple geometry and 4K texture used 50 credits; the superseded banana used 50, for 100 total from the authorized 300-credit budget. Originals remain outside the repository; the optimized asset has a separate CC BY 4.0 notice to the extent the publisher holds licensable rights.
- Optional 3D-print information uses mesh-derived volume and a labelled geometric time approximation. Installed slicers are discovered locally by bundle ID; only names and IDs go to the viewer. A separate explicit Bambu calculation supports native-source STL with Generic PLA/PETG, A1 mini 0.4 mm nozzle, 0.2 mm layers, 15% infill and Textured PEI Plate. It copies the original to a temporary job, merges only bundled profiles (not personal presets), uses a separate temporary settings directory and deletes job files afterwards. The calculation sends no print commands. Native cancellation and a 40-second process deadline stop the job; user viewport transforms are not exported.
- No in-app purchases, subscriptions, advertising, user registration, login item, camera, microphone, location or contacts permissions.

## Remaining release gates

1. **Source publication completed; retain corresponding-source releases.** The public repository contains application source, build instructions, original demo/test fixtures, licenses, asset notices and privacy/support pages. A source-package script bundles the pinned CAD-library sources with each committed release tree. Re-run it after changes and attach the resulting archive to any binary release. Credentials, provisioning keys and customer models are excluded.
2. **Establish valid distribution signing.** A fresh keychain query found **7 valid Apple Development identities**, **0 Developer ID Application** identities and **0 Apple/Mac App Distribution** identities. Xcode had rejected the particular development identity selected earlier; this is not evidence that all development identities are invalid. No valid App Store distribution identity/provisioning was established in this task. Local previews are ad-hoc signed. A direct-download binary also needs an appropriate Developer ID signature and notarization for normal public distribution; do not instruct users to disable Gatekeeper.
3. **Complete LGPL distribution obligations before distributing a binary.** Publish the exact corresponding source archives and rebuild instructions for the distributed importer/WASM/OCCT versions, preserve all notices and the applicable OCCT exception, and verify recipients retain their LGPL rights under the chosen App Store EULA/distribution/DRM arrangement. Open-sourcing Form's own MIT code does not by itself resolve those obligations. Obtain a distribution-specific rights review if the terms remain uncertain.
4. **Confirm the Apple account and publisher identity.** The requested brand is FDMwerk and the supplied support email is support@fdmwerk.de. The public FDMwerk imprint names Christoph Kielhorn. Check these against the actual Apple Developer account, legal agreements and EU trader information. Apple permits a different registered trade/DBA developer name for qualifying organization accounts; an Individual account uses the individual's legal developer name. A newly created GitHub organization does not create or convert an Apple organization account.
5. **Complete App Store Connect metadata.** Confirm name and bundle-ID availability (`de.fdmwerk.form`), age rating/content questionnaire, category, intended territories, free pricing, export-compliance answers and reviewer contact person/phone. The preparation file contains the supplied support email and intended URLs. Do not invent contact data or accept Apple agreements without the required user authorization.
6. **Produce final screenshots from the final app.** Use owned demo models, not customer files, and supported Mac dimensions such as 1280 × 800, 1440 × 900, 2560 × 1600 or 2880 × 1800. Do not advertise features absent from the final binary.
7. **Finish compatibility and robustness checks.** Re-test saved navigation/display settings and the completed color/tree changes, and cover representative embedded textures, OBJ/PLY/3MF/glTF/GLB, CAD assembly variants, invalid input, large files and long sessions. Test macOS 14 and an Intel Mac before claiming those platforms have been tested. The development system is Apple Silicon on macOS 27; a universal build alone is not compatibility validation. Audit native/bundled dependencies again at release time.
8. **Validate the dedicated Store flavor.** App Review 2.4.5 requires a sandboxed, self-contained Mac bundle; 2.5.2 restricts external code that adds functionality. As a conservative interpretation of those rules, configuration `AppStore` defines `FORM_APP_STORE` and compiles out the Bambu CLI runner and Blender Python importer. It retains the bundled viewer, geometric estimate and standard original-file NSWorkspace handoff. Blender is excluded from compatible-app menus in this flavor. A native capability handshake hides the CLI action, and forged bridge requests are rejected natively. Normal `Release` retains both desktop integrations. `scripts/archive.sh` now explicitly archives `AppStore` to `Form-AppStore.xcarchive`. Test and describe the exact Store variant; this design reduces the identified risk without proving Apple acceptance.
9. **Validate and submit the signed archive.** Run Xcode Organizer/App Store Connect validation and resolve actual findings. No review by Apple has occurred. The preview must not be presented as certified metrology or a full parametric CAD modeller.

## Native Mac / HIG review

This product uses **AppKit and WKWebView on macOS**. UIKit-only rules for iPhone/iPad do not define its native window implementation. Apple’s current menu-bar, windows and accessibility guidance is the applicable design reference; this is a focused review, not a certification of every guideline.

Implemented native checks/fixes: the window retains standard close/minimize/full-screen controls and edge resizing; a dedicated 28-point titlebar strip performs native window dragging without taking model orbit gestures; initial size is constrained to the visible screen for MacBook usability. Native Open/Save sheets provide standard file selection and overwrite confirmation. Cmd+O, Cmd+Comma, Cmd+Q, Cmd+C/V/A and Cmd+Shift+S are represented in the menu bar. Own icon artwork is loaded before Dock activation and explicitly supplied to About. Unavailable actions in the viewer remain disabled; local file/URL bridge boundaries and serial import errors are tested.

Remaining desktop polish to assess before Store submission: complete conventional Services/Hide/Window/Help menu coverage where appropriate; verify VoiceOver naming, keyboard focus, full keyboard navigation and text editing undo in the final installed app; inspect increased contrast/reduced motion, long labels/RTL, fullscreen and minimum-size layouts on the target MacBook. The bottom model toolbar follows the requested design, so critical commands should also remain reachable through the header/keyboard and should be checked when the lower window edge is off screen. These are targeted verification tasks, not evidence of a present App Review rejection.

## Optional slicer evidence

The installed Bambu Studio CLI reported version **2.9.1.70** and its documented local slice/config flags. An owned, closed 20 mm cube was sliced with resolved bundled presets. A separately compiled, ad-hoc signed probe used the app-sandbox and user-selected-file entitlements, deliberately **omitted network-client**, and reported a real sandbox container. The actual production `FormBambuSlicePolicy` succeeded there for PLA (**1316.07 s; 3.6717 g**) and PETG (**1700.90 s; 3.6476 g**). No cloud or printer-send command was used. These are slicer predictions, not measured physical print times, and apply only to that installed version and fixed preset setup. The first PETG trial correctly failed on Cool Plate; the supported adapter explicitly uses Textured PEI Plate.

Production-policy tests cover profile inheritance/include precedence, cyclic profile rejection, material allowlisting, bounded parsed time/weight, actual process timeout, cancellation, cancellation before launch, duplicate filename identity and installed-slicer classification. The integrated viewer/native request/selection/cancellation flow must still be verified in the final built app.

## LGPL and Store terms assessment

The bundled LGPL 2.1 text, section 6, requires notices and a route to modify/relink the library, including permission for debugging those modifications. The public MIT application source and separately replaceable importer resources support that route, provided the exact matching library source and working rebuild instructions accompany the binary release. Apple’s current Standard EULA section (a) explicitly excepts restrictions to the extent permitted by open-source component licenses. Therefore a blanket statement that Apple forbids LGPL or reverse engineering is inaccurate. Apple’s Developer Program agreement still requires compliance with FOSS terms and compatibility with signing/content-protection terms. Verify the selected EULA and the final distribution/rebuild process rather than assuming either automatic incompatibility or automatic compliance.

## Product limitations to retain in public copy

Measurements use display triangles and depend on correct file units. Sections are uncapped display clipping, docking aligns bounding faces without constraints or collision checks, and scene transforms/measurements are session-only. The app does not offer exact CAD volume, CAD export, native proprietary CAD import, or every gesture of the navigation-profile applications. Large synchronous CAD tessellation can pause the viewer. Do not claim support for “all CAD formats”.
